# SoloAvalon 提示词质量迭代阶段总结

本文记录近期围绕 AI 玩家提示词质量、派西维尔身份争夺、真人桌感和样本评估器的阶段性改进。当前阶段已经推进到 `prompt.v40`，重点不再是继续追加禁句，而是把“公开发言是否产生真实桌面动作”作为核心质量标准。

## 目标

- 让 AI 更像真人阿瓦隆玩家：会争车位、压理由、给责任顺序，而不是只说信息少、先观察。
- 补强关键身份争夺，尤其是派西维尔围绕梅林/莫甘娜候选的解释权争夺。
- 避免公开泄露隐藏视角、任务牌、自身任务行动或不该知道的身份真相。
- 降低票型事实错误，尤其是把多人同票说成“唯一赞成/唯一反对”。
- 用多 seed 样本、评估器和子代理审阅来检验质量，而不是只凭提示词文案自我判断。

## 真人玩法参考带来的原则

参考阿瓦隆规则与玩家攻略后，当前 prompt 采用的核心原则是：

- 派西维尔知道两名梅林候选，但不能区分梅林和莫甘娜，因此不应直接摊开候选关系。
- 真派西维尔的价值不是“报身份”，而是半藏半露地保护真梅林、试探莫甘娜、抢候选解释权。
- 候选判断应通过车位、投票、任务结果、保人/排人动作和对跳反应来表达。
- 莫甘娜、刺客和忠臣也可能借用派西维尔姿态，制造假保护、挡刀或逼真视角露头。
- 真人桌上的有效动作通常是点名、追问、换车、条件票、失败后归责，而不是泛泛观察。

## 阶段一：身份叙事从“有意识”到“能说出口”

代表版本：`prompt.v12` 到 `prompt.v19`

主要改进：

- 引入“身份叙事债”：一旦出现梅林候选、派西维尔姿态、保护线或对跳，公开发言必须回应这条叙事。
- 要求派西维尔把私下候选判断转成公开可否认动作，例如软保一人、拆一条保护关系、追问谁在急着排/保谁。
- 明确真派不要“报拇指”，即不要把两名候选直接公开绑定。
- 把身份动作写成更口语的桌面短句，例如“玩家X一直替玩家Y卸压”“我先偏保玩家X这轮上车”。

解决的问题：

- 早期 AI 经常只在 `private_reason_summary` 里分析候选，公开发言却像普通好人一样绕开身份线。
- 派西维尔容易忘记自己有候选视角，或者过早把两个候选一起暴露。

遗留问题：

- 公开句仍容易变成“我关注这条线”“后续再看”这种空泛表态。
- 模型会复读示例句，形成新模板。

## 阶段二：从模板禁句转向桌面动作

代表版本：`prompt.v20` 到 `prompt.v34`

主要改进：

- 把“观察候选反应”改写成可被全桌回应的压力，例如上车吃压力、解释为什么排人、失败后先问谁。
- 强化首轮和组队阶段的口语化动作：带谁、为什么带、暂时不带谁、炸了先问谁。
- 发现禁句越堆越多会诱导模型绕词表后，开始转向动作分流：同一轮已有玩家追问过某个排除点时，后续玩家必须换动作。
- 要求刺客、莫甘娜和忠臣也参与身份叙事，不要只中立复读。

解决的问题：

- “先走一车”“看看结果”“看看反应”“多一个视角”等句子明显减少。
- 组队和发言开始出现车位诉求、条件票、失败归责、保护/拆线等动作。

遗留问题：

- 模板短语可以减少，但不等于身份争夺质量变高。
- 有些样本清除了禁句，却仍没有真正围绕候选解释权进行争夺。

## 阶段三：票型事实和任务牌边界

代表版本：`prompt.v30` 到 `prompt.v38`

主要改进：

- 任务失败后禁止用“我没出失败票”“我是成功票”自证。
- 成功任务不能说成验人，避免“认这张底牌”“打这张任务牌”。
- 引入票型 grounding：公开引用上一轮、首轮、唯一票、反对者或赞成者前，私下理由必须先列出对应赞成/反对名单。
- 评估器开始抓 `vote_fact_misread_count` 和 `vote_reference_without_grounding_count`。

解决的问题：

- 公开发言不再允许把隐藏任务牌或任务行动当证明。
- 对“唯一赞成/唯一反对”的事实误读有了可审计检测。

遗留问题：

- v37/v38 样本仍出现公开引用票型但私下没有列名单的情况。
- 模型会把“成功票”任务牌误触发为投票 grounding，后来评估器已修正这一假阳性。

## 阶段四：结构动作优先的 v39/v40

代表版本：`prompt.v39` 和 `prompt.v40`

主要改进：

- `prompt.v39` 不再继续扩禁句表，而是把质量判断改成结构动作：点一个人、追一个理由、给一个后果动作。
- `template_phrase_count` 仍保留为诊断，但不再作为质量门硬失败。
- 评估器收窄候选关系压力：普通“为什么没带玩家X”只算车位追问，不冒充派西维尔/候选争夺。
- 候选关系压力并入 `identity_contest_action_count`，避免“候选压力有了但身份动作没有”的口径脱节。
- `prompt.v40` 进一步要求票型 grounding 是生成前动作：私下理由第一行先列赞成/反对名单，否则公开不引用票型。
- `prompt.v40` 要求候选回扣一次只处理一个核心对象，避免两名候选一起问、一起观察、一起解释。
- 评估器新增反例边界：普通“没带某人，即使失败你要解释”不算候选压力；跨句的普通组队追问和“下一轮我想上车”不拼成候选压力。

解决的问题：

- v40 样本未再出现唯一票事实误读或票型 grounding 缺口。
- 评估器更少被普通车位压力污染。
- 子代理复审认可当前方向：不要继续堆禁句，保留结构动作口径。

遗留问题：

- v40 seed39 仍未通过完整质量门，失败点是 `missing_candidate_relation_pressure` 和 `private_candidate_without_public_action`。
- 派西维尔私下知道候选后，公开仍可能只说“先观察车外态度”“你被排除在外有什么想说的吗”，没有形成明确候选解释权争夺。
- 模板感仍有残留，但它不是当前主要阻塞项；主要阻塞项是候选私有判断没有稳定转成公开桌面动作。

## 当前评估器如何检测质量

评估脚本：

```powershell
.venv\Scripts\python.exe scripts\prompt_log_evaluator.py logs\<sample>.json
```

输入：

- `speeches`：公开发言。
- `decisions`：AI 决策记录，重点读取 `output.public_message` 和 `output.private_reason_summary`。

主要指标：

- `identity_contest_action_count`：公开身份争夺动作数量，例如保护、拆线、上车吃压力、要求解释。
- `candidate_relation_pressure_count`：真正围绕候选关系施压的公开动作数量。
- `private_candidate_decision_count`：私下理由提到候选、保护线或候选关系的决策数量。
- `candidate_public_action_count`：私下提候选且公开确实落成候选压力的数量。
- `candidate_public_action_gap_count`：私下提候选但公开没有落成候选压力的缺口。
- `public_candidate_binding_count`：公开绑定两个候选的风险。
- `pairwise_candidate_trial_risk_count`：让两名候选一起证明、一起解释或一起扛责任的风险。
- `private_leak_claim_count`：用自己任务牌或任务行动自证的风险。
- `overconfident_success_claim_count`：把成功任务说成身份确认的风险。
- `verification_like_task_phrase_count`：把任务说成验人或检验的风险。
- `vote_fact_misread_count`：唯一票等公开票型事实错误。
- `vote_reference_without_grounding_count`：公开引用票型但私下没有先列赞成/反对名单。
- `template_phrase_count`：模板短语诊断项，不再作为硬失败。

质量门硬失败项：

```text
sample_too_short
missing_public_identity_contest_action
missing_candidate_relation_pressure
private_candidate_without_public_action
public_candidate_binding_risk
private_leak_claim_present
overconfident_success_claim_present
pairwise_candidate_trial_risk_present
verification_like_task_phrase_present
vote_fact_misread_present
vote_reference_without_grounding_present
```

当前检测原则：

- 不以禁句作为主裁判。
- 普通车位追问不算候选争夺。
- 候选争夺必须有玩家、公开动作和桌面要求。
- 私下候选判断必须转成公开可回应动作。
- 票型引用必须先有私下赞反名单作为 grounding。
- 样本指标只是第一层，仍需要人工和子代理复审判断真人桌感。

## 已使用的验证方式

- 多 seed DS 短局采样，覆盖 v35 到 v40 多轮变化。
- 对样本运行 `scripts/prompt_log_evaluator.py`，检查质量门和示例。
- 人工抽查关键公开发言和 `private_reason_summary` 是否一致。
- 子代理只读审阅 v35/v37、v39、v40 样本和评估器口径。
- 单元测试覆盖 prompt 文案约束、评估器正反例、票型 grounding、候选压力假阳性。
- 全量测试验证：

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 下一阶段改进方向

### 1. 结构化候选公开动作

推荐优先做轻量结构化，而不是继续追加 `prompt.v41` 文案。

较稳的方案是在不改 JSON schema 的前提下，要求 `private_reason_summary` 对候选相关决策先写一行：

```text
候选公开动作：点玩家X，因为他做了Y，公开要求Z
```

然后评估器检查：

- 私下提候选时是否存在这行。
- 这行里的核心玩家是否进入 `public_message`。
- `public_message` 是否包含动作和要求，而不是只说观察。

这个方案的好处是风险较低，不需要改后端解析契约，也能逼模型先规划再发言。

### 2. 分阶段候选动作菜单

派西维尔在不同阶段需要不同公开动作：

- 首轮：单点一个候选或一个排/保候选的人，问组队理由或车位态度。
- 任务成功后：不把成功当验人，只临时保一轮或要求继续吃压力。
- 任务失败后：按车队、投票、组队理由归责，不能用任务牌自证。
- 有人跳身份后：判断对方是挡刀、坏人抢解释权，还是真视角被迫露头。

后续可以把这些动作菜单做得更短、更阶段化，减少长 prompt 中模型漏读的概率。

### 3. 增加样本质量分层

当前质量门是硬通过/失败。下一步可以增加分层评分：

- P0：隐藏信息泄露、任务牌自证、票型事实错误。
- P1：私下候选没有公开动作、候选绑定风险。
- P2：模板感、发言冗长、口语化不足。

这样阶段总结会更清楚：哪些问题必须修，哪些只是风格打磨。

### 4. 保留子代理审阅

子代理审阅最有价值的点是能发现评估器假阳性和样本“看似过门但不像真人”的地方。后续每个阶段建议至少让子代理检查：

- 是否又回到禁句判断。
- 候选压力是否是真候选解释权争夺。
- 是否有公开事实错误。
- 坏人和忠臣是否也参与身份叙事，而不是只让派西维尔工作。

## 当前阶段结论

本轮迭代已经把提示词质量判断从“避开禁句”推进到“结构动作优先”。票型 grounding 和任务牌边界有明显改善，评估器也更能区分普通车位压力与候选身份争夺。

仍需改进的核心不是继续加禁句，而是让派西维尔的私下候选判断稳定转化为公开、单点、可回应的候选解释权动作。下一阶段应优先做结构化候选公开动作自检，并用多 seed 样本和子代理复审验证它是否真正改善真人桌感。
