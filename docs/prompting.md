# AI 提示词规范与功能说明

本文档总结 SoloAvalon 当前 AI 提示词的设计边界、配置能力和维护约定。目标是让模型像合法玩家一样参与讨论和决策，同时避免把调试信息、配置元信息或隐藏真相泄露给模型。

## 核心原则

- 只使用当前玩家合法可见的信息，包括自己的身份视角、公开玩家列表、公开发言、公开投票结果、任务结果、个人判断记录和当前可执行动作。
- 不向模型发送原始 `private_view`、`public_state`、`recent_public_events`、`legal_actions` 等 JSON 上下文字段。
- 不向模型发送提示词版本号、配置键名、默认开关、推荐身份组合等元信息。
- 公共规则、常用动作规则和 JSON 契约前置；玩家开局视角固定，事件和私有记录按时间追加，当前状态与合法参数放在末尾。
- 个人判断记录是过去的判断与计划，不是已确认事实；后续可以修正，但不改写历史，也不能把它作为公开证据。
- 后端是唯一规则裁判。模型只能提出动作意图，合法性由后端校验。

## 配置文件

可提交的提示词配置位于：

```text
config.example/prompt_templates.json
```

本地可通过环境变量覆盖：

```powershell
$env:SOLOAVALON_PROMPT_CONFIG="E:\path\to\prompt_templates.json"
```

真实模型配置仍位于被 git 忽略的 `config/llm_profiles.json`，不要把真实 API Key 或供应商配置写入提示词配置。

## 发送给模型的结构

当前默认模板为 `prompt.v41`，上下文构造版本为 `context-builder.v2`。模型消息结构如下：

```text
【系统】
【动作规则】
【动作 JSON 格式声明】
【本局配置】

【你的视角】

【活动日志】
公开事件、个人判断和私有查验结果，每条记录使用独立的 user message

【本次行动】
当前状态、请求动作、合法参数
```

前四个标题位于同一条 system message。玩家视角是独立的 user message；活动日志标题、每条历史记录和末尾行动请求也分别是 user message。即使暂无事件，也保留固定的活动日志标题，不插入下一次会消失的“暂无活动”消息。

### 拼接流程

提示词从游戏状态到模型请求的调用链如下：

1. `GameRunner` 在读取游戏状态的同一事务中读取已提交事件，分别投影出公开事件和当前玩家的个人判断记录，再释放数据库连接。
2. `AiPlayer._decide()` 调用 `ContextBuilder.build()`，把 `GameState`、当前玩家、当前阶段、公开事件和个人判断整理成 `AiContext`。
3. `ContextBuilder.build()` 生成两类上下文：
   - `stable_prefix`：稳定前缀，用于 system message。
   - 动态上下文：玩家私有视角、公开状态、近期公开事件、个人判断、当前玩家合法获得的查验记录和当前合法动作。
4. `PromptBuilder.build_messages()` 把 `AiContext` 渲染成 OpenAI-compatible Chat Completions 的 `messages`。
5. `LlmProvider.chat_completion()` 把 `messages` 放入请求体并发送给模型接口。

当前最终消息结构是：

```python
[
    {"role": "system", "content": context.stable_prefix},
    {"role": "user", "content": "【你的视角】..."},
    {"role": "user", "content": "【活动日志】"},
    {"role": "user", "content": "#0001 对局开始。"},
    {"role": "user", "content": "【个人判断记录·speech】\n此前的私下判断摘要"},
    # 后续事件继续追加，不改写已有消息。
    {"role": "user", "content": "【本次行动】当前状态、动作和合法参数..."},
]
```

`messages[0]` 保持为 `system = context.stable_prefix`，其 hash 覆盖完整公共规则、常用动作规则、输出格式和本局配置。后续顺序固定为开局玩家视角、活动历史、本次行动。切换行动类型不会改变 system 内容。

`dynamic_private_suffix` 是 `ContextBuilder` 生成的结构化上下文快照，主要用于测试、审计和确认隐藏信息边界；当前不会直接发给模型。最终发给模型的是 `PromptBuilder` 渲染后的自然语言段落，避免暴露 `private_view`、`public_state`、`recent_public_events`、`legal_actions` 等原始字段名。

### 系统与本局配置

`prompt.v41` 将重复的表达、票型核对和候选约束合并至通用规则；四类常用动作只保留各自特有要求，身份专属策略主要保留在当前角色玩法中。以下版本号用于说明历史策略来源，不表示这些重复文案仍会逐条发送。

包含：

- 真实桌游发言风格：积极争取上车、质疑车队、表达上车/下车意愿。
- 发言/投票自洽：玩家需要承接自己上一轮公开立场，后续投票应能被公开发言解释；若改票或改变组队方向，需要说明新信息、新压力或身份叙事变化。
- 票型引用核对：`prompt.v11` 要求模型引用他人历史投票、组队、任务成员或发言原话前，必须先在活动日志中核对具体记录；没有把握时应改成追问，避免把反对说成赞成或捏造未发生的矛盾。
- 套话降噪：避免全桌反复使用通用安全套话，也避免换成同义安全句；同一轮尽量从不同矛盾、车位压力或身份叙事切入。`prompt.v19` 减少在 prompt 里完整复述禁句，改为提供正向替代表达，例如带谁、暂时不带谁、炸了先问谁、谁这轮别被打死，降低模型照抄负面示例的概率。`prompt.v39` 继续把判断中心从禁句表转到结构动作：一段合格发言应能点一个人、追一个理由、给一个后果动作；模板短语只作为诊断信号，不再作为质量门的硬失败。
- 局势目标判断：每次行动先判断本轮要争取车位、要求谁下车、保护谁、施压谁，或制造/拆解哪条叙事。
- 话语权动作：围绕车队、票型、任务压力、他人身份叙事和公开矛盾主动推进讨论。
- 条件性身份扮演：身份宣称、跳身份、反跳、抢身份、挡刀和诈身份是可选公开发言策略，不是固定动作。
- 身份叙事债：`prompt.v12` 参考真人局里“不要无脑跳派，但要争候选解释权”的打法。一旦场上出现派西维尔、梅林候选、保护线或对跳，玩家不能只说“先观察”；公开发言或组队说明要回答自己站哪条候选线、拆哪条候选线、反跳谁、逼问谁在保护谁，或为什么暂时替某条线挡一下。`prompt.v13` 进一步补充安全动作菜单：软保一人、拆一条保护关系、逼问某人为什么急着排/保某人、把候选压力转成车位压力；优先点单人或行为线，不公开绑定两个真实候选。`prompt.v14` 把动作改成更能直接说出口的短句，例如“玩家X一直替玩家Y卸压”“玩家X急着排玩家Y”“我先偏保玩家X这轮上车”“这不像普通好人互相评价”。`prompt.v15` 继续要求用自己的话完成动作，避免整局复读示例句，并压制“责任链清晰”“这条线我先记着”“后续再看”等新模板。`prompt.v16` 要求当私下候选关系影响本轮态度时，公开必须落一个不泄露身份的动作，不能只说车队结构。`prompt.v17` 针对 DS 小样本里“这条线我先保着”这种空泛落点，要求公开动作必须点出至少一名玩家或一个具体行为关系。`prompt.v19` 根据真人派西维尔资料补充“不要报拇指”的边界：真派不应把两名候选直接摊开，而应通过车位、投票、候选派票和对跳反应收集信息；有人抢跳派西维尔时，先判断是候选挡刀、坏人抢解释权还是忠臣挡刀，再决定是否反跳或拆线。
- 身份姿态选择：每次公开发言前先决定自己要扮演普通好人、可信上车位、强势推理位、保护位、反跳位、挡刀位、假身份试探，还是有意低调隐藏。
- 组队可解释性：组队理由必须能从公开发言、票型、任务结果、上轮车队结构、场上共识或试车压力中推出；当真实判断与公开证据不匹配时，应优先选择公开上自然且可辩护的车，避免暴露私有视角的最优车。
- 派西维尔话语权：派西维尔是有利身份姿态，也是一种公共话语权资源。非派西维尔在首轮争车位、关键车队前、有人跳身份、票型分裂、任务失败归责、自己被边缘化或需要保护疑似梅林时，都要评估是否短暂借派西维尔姿态，暗示候选判断、保护或转移候选、反跳假派西维尔或质疑候选关系；公开理由必须来自公开信息，连续使用或局势不需要时应退回普通好人/保护位。
- 身份叙事响应：当公开记录已经出现梅林候选、派西维尔姿态、保护/挡刀话术或有人质疑假派西维尔时，发言不能只绕开身份叙事；至少要用一句话选择扮演、反跳、质疑、保护或挡刀，并把它和车队/票型压力连起来。拒绝逼身份也必须表现为保护位或挡刀位话术，而不是简单说信息少、太早、先观察。假扮派西维尔不能凭空硬报未公开候选名单，应优先使用可进可退的保护、候选解释或挡刀话术。
- 公开姿态落地：身份姿态必须体现在公开发言里，不能只写在私下理由中；如果选择保护位、挡刀位或派西维尔姿态，公开发言必须明确保护/拆解至少一条具体叙事。
- 姿态不是身份标签：不要公开自称“我是保护位”“我是挡刀位”。保护位/挡刀位应通过保人、拆线、挡话和换车诉求表现出来。
- 半露视角边界：佯装暴露身份视角时要半真半假、可否认，可以说“我这边更认这个方向”“我偏保玩家X这轮上车”“这条保护关系不自然”，不要说成系统视角、验人结果、真实阵营或不可质疑的确定身份。公开发言也不能说“我投了成功”“我没出失败票”来证明自己，应改成“从我的立场我不认这张锅”“同车其他人需要解释”。
- 私有信息降噪：拥有合法私有信息的身份也不能把最优答案直接翻译成连续精准的组队、投票和发言；特别是梅林要同时评估任务胜率和刺杀暴露风险，避免让车队结果本身暴露私有视角。`prompt.v10` 进一步要求梅林在连续两次精准避坏或反对含坏车后，非决胜行动优先降低可读性，例如跟随公开共识、保留公开可信但私下有风险的位置、只投票不强带队，或让别人先提出正确方向。
- 桌面话术降标签化：公开发言少用“保护位”“派西维尔视角”“验人”等身份标签，多用“我偏保玩家X”“玩家X急着排玩家Y”“玩家X一直替玩家Y卸压”“从我视角看”“按当前任务结果”“我暂时只能怀疑”“队长解释一下为什么这样组”等动作和限定词。
- 推理限定：除非规则公开结算已经证明，否则不要说“确定”“铁好”“铁坏”“验出来”。失败任务后应说“从我视角这几个人需要解释”，而不是把嫌疑二选一说成全桌确定事实。
- 其他玩家的自称身份只是待验证信息，需要结合公开发言、组队、投票和任务结果判断真假。
- 玩家人数。
- 好人/坏人人数。
- 每轮任务人数。
- 每轮任务失败所需失败票数。
- 本局实际身份和身份机制说明。
- 已启用的扩展机制，例如湖中仙女；启用与否来自当前对局状态，而不是 prompt 配置的默认值。

不包含：

- `Prompt 模板版本`。
- `推荐身份组合`。
- 配置开关名称，例如 `enabled`。
- 默认启用人数、默认不加入推荐组合等配置管理说明。
- 未启用的可选身份或机制。

### 你的视角

只包含整局不变的开局视角：当前玩家编号、身份、阵营、当前角色玩法、已启用的进阶玩法、公开玩家列表和合法开局信息。

- 梅林：可见非莫德雷德坏人。
- 派西维尔：可见包含梅林和莫甘娜的候选。
- 可互认坏人：可见同伴；奥伯伦不参与互认。
- 崔斯坦／伊索尔德：可确认搭档为好人。
- 普通忠臣：无额外开局信息。

湖中仙女等后续获得的信息不回填此消息。结构化 `private_view` 仍保留完整合法视角供审计使用，但不会直接发送给模型。

### 固定动作规则与 JSON 格式

`propose_team`、`speak`、`vote`、`mission_action` 的规则和输出格式按固定顺序放入 system。开头明确只应用当前请求对应的规则，避免把其他动作的要求套入本次输出。

- 通用规则负责公开事实核对、立场自洽、表达方式、候选单点约束和隐藏信息边界。
- 组队规则负责公开可解释的车队、带人／排人原因和失败归责。
- 发言规则负责具体桌面动作、首轮候选回扣和轻开身份线的条件。
- 投票规则负责支持／反对与近期公开立场一致，以及改票条件。
- 任务规则负责坏人的成功／失败选择，保留关键任务默认出失败及刺杀胜率例外。

角色基础玩法只追加当前角色的差异策略，不再次完整复述通用要求。刺杀 `assassinate` 和湖中仙女 `use_lady_of_lake` 的短规则及 JSON 格式仍仅在对应行动末尾临时声明。

### 活动日志与私有记录

每个已生效的事件渲染为独立 user message。已有记录不随阶段切换或新任务结算重写，后续内容只向历史末尾追加。

公开事件保留：组队、公开发言、结算后的赞成／反对名单、任务结果及成功／失败票数、谁使用湖中仙女查看了谁、刺杀目标及结算胜者。未结算票型和单个玩家的任务牌不会展示。

#### 个人判断记录

`AiPlayer` 将解析后的 `private_reason_summary` 保存为 `strategy_summary`。读取当前对局已提交的 `ai_decision` 审计事件时，仅提取当前玩家、`validation_status=valid` 且有实际内容的摘要。

```text
【个人判断记录·vote】
我当时倾向反对这辆车，因为队长尚未解释换人原因；下一轮核对他的解释。
```

- 不读取其他玩家的摘要，也不复制原始回复、提示词审计或整个 private payload。
- 失败、解析重试中未提交的结果和因状态变化被丢弃的结果不进入个人历史。
- 缺失摘要、纯文本输出对应的占位说明不作为判断记录；后端直接提交的好人成功牌不编造摘要。
- 使用原有摘要，不调用模型二次总结；统一将内部玩家编号渲染成桌面称呼，不修改其判断含义。
- 原始审计事件先于同一步规则事件提交，个人记录因此表示“决策时的判断”，不表示已经知道随后的任务或票型结算。
- 记录以此前的公开事件数量为位置锚点，不占用或改变公开日志编号；重启后从已有事件重建，无需新表或进程内记忆缓存。

公开 API 和普通对局导出仍使用原有公开字段投影，不包含这些个人记录。现有记忆快照继续保留，但不与审计摘要重复加入 prompt。

#### 私有查验记录

湖中仙女的公开使用记录之后，为查验者单独追加阵营结果；被查验者和其他玩家只能看到公开部分。结果不再重复写入开局视角。

当调用方没有提供完整历史，或显式截断了对应公开事件时，仍以注明获得轮次的独立私有记录提供当前玩家已知的结果，避免丢失合法信息。默认完整历史用于前缀稳定性验收；主动截断旧历史本身会改变前缀。

### 本次行动

最后一条消息仅包含当前轮次、阶段、队长、车队、连续否决次数、强制组队状态、已完成任务结果、湖中仙女持有者，以及本次动作的合法参数。

常用动作不再重复策略长文或 JSON 契约。刺杀和湖中仙女保留按需临时契约。模型只能提交动作意图，动作合法性继续由原有解析器和后端规则校验；好人的任务成功由后端直接提交，不请求模型。

## 角色与身份提示

角色基础文案分为三层：

- `role_descriptions`：本局配置中的身份机制和基本可见事实。
- `role_gameplay`：玩家视角中的默认角色玩法，包含身份目标、局势判断、身份姿态选择、话语权动作和条件性身份扮演建议。
- `role_strategy_tips`：玩家视角中的角色进阶玩法，只在进阶模式开启时展示，用于补充更细的节奏控制、隐藏/误导/保护和刺杀判断。

这些文案会按当前玩家身份展示，不会把其他玩家的隐藏身份真相暴露给当前玩家。

当前默认策略会强化不同身份的桌面打法差异：

- 好人会主动争夺可信话语权，围绕上车/下车、票型、任务结果和身份叙事逼出更多公开信息，并选择普通好人、可信上车位、强势推理位、保护位、派西维尔姿态或挡刀位等身份姿态。
- 梅林会用公开逻辑引导正确车队，通常扮演普通忠臣、谨慎推理位或愿意上车的好人，必要时短暂借用派西维尔姿态制造候选迷雾；组队前会检查队伍是否能被公开记录解释，避免连续按隐藏真相精准排除坏人，或让组队、投票和发言长期呈现同一条精准排雷线。非决胜轮可以保留可解释的不完美，例如跟随部分公开共识、放进公开记录较强的争议位，或扶持其他好人领队来降低梅林感。当已知坏人在车上时，不能只用“隐藏身份所以支持”，而要选择软反对、结构性质疑、条件支持、替代车或失败后归责预案等可否认动作。
- 派西维尔会在辨别梅林/莫甘娜时制造保护性模糊，必要时公开或半公开扮演派西维尔、反跳假派西维尔、扮演保护位或挡刀位，但避免过早卖出候选关系；每次私下理由需要说明候选关系如何影响本轮态度，公开发言至少体现保护、混淆或观察候选反应中的一种。`prompt.v12` 强化“半藏半露地抢候选解释权”：真派应点名一条要保的线、一条要拆的线，或逼问谁在借候选关系带票。`prompt.v13` 要求第二轮还没人谈候选时，派西维尔也要用公开车队或票型包装，轻开一条身份线，但不说候选身份、不公开绑定两个真实候选。`prompt.v15` 要求轻开身份线时用自己的话完成动作，避免把示例句变成新模板。`prompt.v16` 要求私下因为候选关系改变态度时，公开必须用不泄露身份的动作表达一部分。`prompt.v19` 补充真人局边界：真派不要报拇指，而是用逻辑、车位、投票和候选反应收集信息；遇到抢跳时先判断对方是在挡刀还是抢解释权。`prompt.v20` 进一步要求“观察候选”必须落成桌面压力，不能只说自己关注谁。`prompt.v21` 要求这类压力优先落到候选本人，或落到推、保、拆候选的人身上，避免真派只去压一个与候选关系无关的普通车位玩家。`prompt.v22` 明确：当候选领队排掉另一候选时，优先追问领队为什么排他，而不是只申请自己上车。`prompt.v23` 要求每次涉及候选都做候选回扣自检，公开句必须点到候选本人，或点到推、保、排、跳过候选的人。`prompt.v25` 把首轮候选领队带人也纳入回扣，避免真派只说信任和配合。`prompt.v39` 把派西维尔质量判断继续口语化：不是说出“我像派”才算争夺，而是能在车位、投票、失败归责和候选互动里抢解释权；普通车位追问不能替代候选争夺。`prompt.v40` 进一步要求候选回扣单点：公开一次只处理一名候选或一段候选相关互动，避免把两名候选一起问成普通被排除者。当某个候选因持续纠偏被集火时，不应简单跟压，而应通过候选双评、挡刀、吸收视角嫌疑或拆刺客诱导来保护候选空间。
- `prompt.v17` 要求派西维尔的公开保护/拆解必须落到玩家或公开行为上，不能只说“这条线我先保着”；这能把候选判断转成真人桌上能听见、但仍可否认的争夺动作。
- 忠臣会更主动地要位置、逼解释、建立信任链；在争上车、保护强势好人、压制可疑领队、拆身份叙事或给疑似梅林挡刀时，可短暂假装派西维尔、反跳假派西维尔、反压假派西维尔、轻开身份线或挡刀，但不能把猜测说成验人。
- 坏人会主动选择假身份姿态，尤其可扮演假派西维尔来误导候选关系、保护错误对象、逼真视角露头或质疑真视角；刺客会逼真派西维尔或挡刀忠臣表态，莫甘娜会假装懂候选关系来诱导派西维尔站错线，并可在无人开身份线时主动开一条假的保护线或错误质疑线。坏人同时避免固定每次强冲或每次出失败票。支持含坏人的车时，需要预埋后续叙事钩子，例如谁承担组队责任、失败后优先压谁、自己为什么仍可信，或下一轮换掉哪个位置。
- 关键任务中的坏人会优先考虑任务胜利路径：当好人已有两次成功且当前失败能阻止第三次成功时，如果车上坏人数量足以满足失败票需求，默认应出失败并准备推锅，而不是无条件隐藏到刺杀。
- 奥伯伦这类无互认坏人在候选叙事已触发时，默认要参与身份争夺，优先用保护位或假派西维尔姿态搅混候选关系，而不是只用“信息少、先观察”退出讨论。
- 刺客会结合跳身份、挡刀、被保护关系和任务纠偏记录判断谁最像梅林。

当前覆盖身份包括：

- 亚瑟的忠臣 / 忠臣。
- 梅林。
- 派西维尔。
- 刺客。
- 莫甘娜。
- 莫德雷德。
- 奥伯伦。
- 爪牙。
- 崔斯坦。
- 伊索尔德。

## 进阶模式开关

配置项：

```json
"role_tip_detail": {
  "enabled": false,
  "label": "进阶模式",
  "role_tips": {}
}
```

默认关闭。关闭时，模型仍会收到增强后的角色基础玩法，包括身份目标、局势推进、身份姿态选择、话语权动作和条件性身份扮演。

打开后，会在当前玩家自己的角色基础玩法后追加角色进阶玩法，例如更细的发言节奏、隐藏方式、误导方式、保护方式、刺杀判断方式等。模型不会看到 `role_tip_detail`、`enabled` 等配置键名。

进阶模式适合用于：

- 进一步细化角色扮演节奏和风险控制。
- 增强不同身份在压力局、关键票型和终局刺杀前的发言差异。
- 让模型更接近玩家攻略中的常见打法，而不是承担默认角色扮演的全部责任。

进阶玩法不适合写入：

- 配置说明。
- “默认开启/关闭”之类元信息。
- 当前玩家不应知道的隐藏身份真相。
- 与当前身份无关的其它身份私密策略。

## 可选机制

配置项 `optional_mechanics` 用于描述可开关机制的文案。机制是否进入模型输入由每局 `enabled_options` 决定。

当前包含：

- 湖中仙女：仅 8-10 人局可开启；第 2、3、4 次任务结算后，持有者查看一名从未持有过湖女的玩家阵营，并转交湖女。
- 崔斯坦：和伊索尔德互相确认对方是好人。
- 伊索尔德：和崔斯坦互相确认对方是好人。

只有启用后的机制才进入 `【本局配置】`。未启用机制不会显示给模型，避免模型把未生效规则当成当前对局事实。

湖女查验结果属于执行查验玩家的合法私有信息，只在该玩家后续 prompt 的活动历史中以 `【私有记录】` 追加，不改写 `【你的视角】`，不进入其他玩家视角。活动日志对其他玩家只展示“谁使用湖女查看了谁”，不展示阵营。

## 推荐身份组合

`recommended_role_setups` 保留为 prompt 配置中的参考信息，但当前建局规则使用后端规则层固化的 5-10 人推荐身份组合。该字段不作为运行时规则裁判来源。

该字段不直接发送给模型。模型只需要知道“本局实际身份”，不需要知道推荐表、默认表或配置来源。

当前规则层只允许 9-10 人局开启崔斯坦/伊索尔德，开启后由后端把两个忠臣替换为这对身份。

## 元信息禁止进入模型输入

以下内容不应出现在最终发给模型的 prompt 中：

- 提示词版本号。
- 配置文件路径。
- 配置键名。
- `enabled`、`default_enabled_for_player_counts` 等开关字段。
- `recommended_role_setups` 或“推荐身份组合”。
- “默认不加入推荐身份组合”。
- “可选扩展身份”等配置性质描述。
- 原始 JSON 上下文字段名。

如果需要记录这些信息，应保存在 AI 决策日志或配置文件中，而不是发送给模型。

## 相关代码

- `backend/app/services/game_runner.py`：读取状态与历史，将公开事件和个人判断传入 AI 决策调用链。
- `backend/app/services/event_visibility.py`：公开字段投影及当前玩家的有效个人判断筛选；公共接口不读取个人判断。
- `backend/app/services/ai_decision_runner.py`：生成并保存决策审计与摘要。
- `backend/app/ai/player.py`：AI 决策调用链；`AiPlayer._decide()` 负责构造上下文、拼接 prompt、调用模型、解析输出并记录 token/cache usage。
- `backend/app/ai/context.py`：构造 `AiContext`、`stable_prefix`、`stable_prefix_hash`、动态上下文和当前阶段合法动作。
- `backend/app/prompting/templates.py`：渲染开局视角、逐条活动历史、个人判断、私有信息和末尾行动。
- `backend/app/prompting/prefix.py`：生成四类常用动作的固定规则及 JSON 契约。
- `backend/app/prompting/config.py`：加载和校验 `prompt_templates.json`。
- `backend/app/prompting/schemas.py`：解析和校验模型 JSON 输出，非法输出会交由后端规则校验或触发 AI 决策错误。
- `backend/app/llm/provider.py`：把 `messages` 放入 OpenAI-compatible Chat Completions 请求体，并读取 token 与缓存命中用量。
- `config.example/prompt_templates.json`：可提交的默认提示词文案、角色标签、事件模板和动作输出契约。

## 维护建议

- 修改提示词展示结构时，优先检查最终生成的 `prompt_messages`，不要只看配置文件。
- 修改文案、角色标签、事件模板或动作输出契约时，优先看 `config.example/prompt_templates.json`。
- 修改拼接顺序、消息 role、玩家视角、活动日志或本次行动格式时，优先看 `backend/app/prompting/templates.py` 和 `backend/app/ai/context.py`。
- 稳定前缀放固定系统规则、四类常用动作规则、对应 JSON 契约和本局固定配置；玩家视角与历史放在其后，当前状态和合法参数只放末尾。
- 当前“增量”优化指让每次请求的前文保持一致，并让活动日志按事件时间顺序追加，避免重排、合并改写旧记录或重复声明常用动作 JSON 格式；OpenAI-compatible Chat Completions 仍然是无状态请求，不应假设 API 只接收 delta 或自动记住上一轮上下文。
- `assassinate` 和 `use_lady_of_lake` 不应进入固定动作 JSON 声明，只在实际请求对应行动时临时声明。
- 决策审计中的缓存策略标记为 `append-only-history-v2`。排查时看 `stable_prefix_hash`、`prompt_tokens`、`cached_tokens` 和 `cache_hit_rate`，优先比较未缓存输入量与整局费用，不只追求命中率百分比。
- 增加角色时，至少补齐身份标签、机制说明、玩法、策略、合法视角规则。
- 增加开关时，区分“配置给系统看的内容”和“模型需要知道的游戏事实”。
- 测试应优先覆盖长期行为，例如合法视角、不泄露原始 JSON、投票和任务结果可读，以及目标、上车/下车、质疑/反跳、合法信息边界等行为关键词簇，而不是绑定某一句攻略文案。
