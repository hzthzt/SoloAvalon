# AI 提示词规范与功能说明

本文档总结 SoloAvalon 当前 AI 提示词的设计边界、配置能力和维护约定。目标是让模型像合法玩家一样参与讨论和决策，同时避免把调试信息、配置元信息或隐藏真相泄露给模型。

## 核心原则

- 只使用当前玩家合法可见的信息，包括自己的身份视角、公开玩家列表、公开发言、公开投票结果、任务结果和当前可执行动作。
- 不向模型发送原始 `private_view`、`public_state`、`recent_public_events`、`legal_actions` 等 JSON 上下文字段。
- 不向模型发送提示词版本号、配置键名、默认开关、推荐身份组合等元信息。
- 前缀内容尽量稳定，便于模型服务端缓存；动态信息集中在玩家视角、活动日志和本次行动中。
- 后端是唯一规则裁判。模型只能提出动作意图，合法性由后端校验。

## 配置文件

可提交的提示词配置位于：

```text
config.example/prompt_templates.json
```

本地可通过环境变量覆盖：

```powershell
$env:SOLOAVALON_PROMPT_CONFIG="E:\path\to\prompt_templates.json"
```

真实模型配置仍位于被 git 忽略的 `config/llm_profiles.json`，不要把真实 API Key 或供应商配置写入提示词配置。

## 发送给模型的结构

当前模型消息分为五段：

```text
【系统】
【本局配置】

【你的视角】

【动作 JSON 格式声明】

【活动日志】

【本次行动】
```

`【系统】` 和 `【本局配置】` 放在 system message 中，用于提供稳定规则背景。`【你的视角】`、`【动作 JSON 格式声明】`、`【活动日志】`、`【本次行动】` 分别作为 user message 发送。

### 拼接流程

提示词从游戏状态到模型请求的调用链如下：

1. `GameService` 在自动推进 AI 行动或真人托管 AI 行动时调用 `AiPlayer`。
2. `AiPlayer._decide()` 调用 `ContextBuilder.build()`，把 `GameState`、当前玩家、当前阶段和公开事件整理成 `AiContext`。
3. `ContextBuilder.build()` 生成两类上下文：
   - `stable_prefix`：稳定前缀，用于 system message。
   - 动态上下文：玩家私有视角、公开状态、近期公开事件和当前合法动作。
4. `PromptBuilder.build_messages()` 把 `AiContext` 渲染成 OpenAI-compatible Chat Completions 的 `messages`。
5. `LlmProvider.chat_completion()` 把 `messages` 放入请求体并发送给模型接口。

当前最终消息结构是：

```python
[
    {"role": "system", "content": context.stable_prefix},
    {"role": "user", "content": "【你的视角】..."},
    {"role": "user", "content": "【动作 JSON 格式声明】..."},
    {"role": "user", "content": "【活动日志】..."},
    {"role": "user", "content": "【本次行动】..."},
]
```

`messages[0]` 必须保持为 `system = context.stable_prefix`。后续 `user` messages 的顺序固定为玩家视角、动作 JSON 格式声明、活动日志、本次行动。

`dynamic_private_suffix` 是 `ContextBuilder` 生成的结构化上下文快照，主要用于测试、审计和确认隐藏信息边界；当前不会直接发给模型。最终发给模型的是 `PromptBuilder` 渲染后的自然语言段落，避免暴露 `private_view`、`public_state`、`recent_public_events`、`legal_actions` 等原始字段名。

### 系统与本局配置

包含：

- 真实桌游发言风格：积极争取上车、质疑车队、表达上车/下车意愿。
- 发言/投票自洽：玩家需要承接自己上一轮公开立场，后续投票应能被公开发言解释；若改票或改变组队方向，需要说明新信息、新压力或身份叙事变化。
- 票型引用核对：`prompt.v11` 要求模型引用他人历史投票、组队、任务成员或发言原话前，必须先在活动日志中核对具体记录；没有把握时应改成追问，避免把反对说成赞成或捏造未发生的矛盾。
- 套话降噪：避免全桌反复使用“认真完成任务、积累信息、让结果说话、不要拖节奏、后续复盘”等通用句式，同一轮尽量从不同矛盾、车位压力或身份叙事切入。
- 局势目标判断：每次行动先判断本轮要争取车位、要求谁下车、保护谁、施压谁，或制造/拆解哪条叙事。
- 话语权动作：围绕车队、票型、任务压力、他人身份叙事和公开矛盾主动推进讨论。
- 条件性身份扮演：身份宣称、跳身份、反跳、抢身份、挡刀和诈身份是可选公开发言策略，不是固定动作。
- 身份姿态选择：每次公开发言前先决定自己要扮演普通好人、可信上车位、强势推理位、保护位、反跳位、挡刀位、假身份试探，还是有意低调隐藏。
- 组队可解释性：组队理由必须能从公开发言、票型、任务结果、上轮车队结构、场上共识或试车压力中推出；当真实判断与公开证据不匹配时，应优先选择公开上自然且可辩护的车，避免暴露私有视角的最优车。
- 派西维尔话语权：派西维尔是有利身份姿态，也是一种公共话语权资源。非派西维尔在首轮争车位、关键车队前、有人跳身份、票型分裂、任务失败归责、自己被边缘化或需要保护疑似梅林时，都要评估是否短暂借派西维尔姿态，暗示候选判断、保护或转移候选、反跳假派西维尔或质疑候选关系；公开理由必须来自公开信息，连续使用或局势不需要时应退回普通好人/保护位。
- 身份叙事响应：当公开记录已经出现梅林候选、派西维尔姿态、保护/挡刀话术或有人质疑假派西维尔时，发言不能只绕开身份叙事；至少要用一句话选择扮演、反跳、质疑、保护或挡刀，并把它和车队/票型压力连起来。拒绝逼身份也必须表现为保护位或挡刀位话术，而不是简单说信息少、太早、先观察。假扮派西维尔不能凭空硬报未公开候选名单，应优先使用可进可退的保护、候选解释或挡刀话术。
- 公开姿态落地：身份姿态必须体现在公开发言里，不能只写在私下理由中；如果选择保护位、挡刀位或派西维尔姿态，公开发言必须明确保护/拆解至少一条具体叙事。
- 姿态不是身份标签：不要公开自称“我是保护位”“我是挡刀位”。保护位/挡刀位应通过保人、拆线、挡话和换车诉求表现出来。
- 半露视角边界：佯装暴露身份视角时要半真半假、可否认，可以说“我这边更认这个方向”“这条线我暂时保/拆”，不要说成系统视角、验人结果、真实阵营或不可质疑的确定身份。公开发言也不能说“我投了成功”“我没出失败票”来证明自己，应改成“从我的立场我不认这张锅”“同车其他人需要解释”。
- 私有信息降噪：拥有合法私有信息的身份也不能把最优答案直接翻译成连续精准的组队、投票和发言；特别是梅林要同时评估任务胜率和刺杀暴露风险，避免让车队结果本身暴露私有视角。`prompt.v10` 进一步要求梅林在连续两次精准避坏或反对含坏车后，非决胜行动优先降低可读性，例如跟随公开共识、保留公开可信但私下有风险的位置、只投票不强带队，或让别人先提出正确方向。
- 桌面话术降标签化：公开发言少用“保护位”“派西维尔视角”“验人”等身份标签，多用“我偏保他”“这条线我先站/先拆”“从我视角看”“按当前任务结果”“我暂时只能怀疑”“队长解释一下为什么这样组”等动作和限定词。
- 推理限定：除非规则公开结算已经证明，否则不要说“确定”“铁好”“铁坏”“验出来”。失败任务后应说“从我视角这几个人需要解释”，而不是把嫌疑二选一说成全桌确定事实。
- 其他玩家的自称身份只是待验证信息，需要结合公开发言、组队、投票和任务结果判断真假。
- 玩家人数。
- 好人/坏人人数。
- 每轮任务人数。
- 每轮任务失败所需失败票数。
- 本局实际身份和身份机制说明。
- 已启用的扩展机制，例如湖中仙女；启用与否来自当前对局状态，而不是 prompt 配置的默认值。

不包含：

- `Prompt 模板版本`。
- `推荐身份组合`。
- 配置开关名称，例如 `enabled`。
- 默认启用人数、默认不加入推荐组合等配置管理说明。
- 未启用的可选身份或机制。

### 你的视角

包含：

- 当前玩家 id。
- 当前玩家身份。
- 当前玩家阵营。
- 当前角色基础玩法；默认已经包含身份目标、局势判断、话语权动作、身份姿态选择和条件性身份扮演建议。
- 进阶模式开启时的当前角色进阶玩法，用于追加更细的节奏控制、保护、误导和刺杀判断。
- 当前身份合法可见的额外信息。
- 公开玩家 id 列表。

不同身份的额外信息不同：

- 梅林：可见非莫德雷德坏人玩家。
- 派西维尔：可见梅林候选，候选中包含梅林和莫甘娜。
- 坏人：可见坏人同伴；奥伯伦不参与坏人互认。
- 崔斯坦/伊索尔德：可互相确认对方为好人。
- 普通忠臣：无额外隐藏信息。

### 动作 JSON 格式声明

`【动作 JSON 格式声明】` 提前声明整局常用动作的输出格式，后续行动请求不重复声明这些 JSON 契约。当前固定声明：

- `propose_team`。
- `speak`。
- `vote`。
- `mission_action`。

`assassinate` 和 `use_lady_of_lake` 不放入固定声明。只有实际轮到刺杀或湖中仙女行动时，才在 `【本次行动】` 中临时补充本次 JSON 格式。

### 活动日志

活动日志按事件时间顺序追加，只保留正常玩家能看到且有决策价值的信息：

- 组队：队长和车队成员。
- 发言：玩家 id 和公开发言文本。
- 投票结果：车队是否通过，具体谁赞成、谁反对。
- 任务结果：成功/失败，以及成功票、失败票数量。
- 湖中仙女：公开展示谁查看了谁；若是当前玩家自己的查验，则额外展示查验结果。
- 刺杀：刺客目标和结算后的胜者。
- AI 行动确认：当前玩家自己的行动完成后记录为“已进行处理”。

活动日志不展示技术事件类型前缀，例如 `SPEECH:`、`TEAM_PROPOSED:`；也不展示单个玩家“已完成投票”“已提交任务行动”这类过程噪音。未结算投票不会公开票型；结算后才展示具体赞成/反对玩家。

### 本次行动

`【本次行动】` 只说明本次要执行什么动作、当前可选参数，以及必要时的临时 JSON 格式。常用动作的 JSON 契约已经在 `【动作 JSON 格式声明】` 中提前声明，不在每次行动里重复。

- 组队：返回车队、公开组队理由和私下判断摘要。
- 发言：返回公开发言和私下判断摘要。
- 投票：返回 `approve` 或 `reject`，不需要公开理由。
- 任务：坏人可选择成功/失败；好人任务行动由后端直接提交成功，不请求模型。
- 刺杀：返回刺杀目标、候选排序和私下判断摘要。
- 湖中仙女：返回查验目标和私下判断摘要。

行动提示会引导模型先判断当前阶段的局势目标和身份姿态，再通过具体话语权动作推进局面，例如争取上车、要求换人、质疑身份叙事、保护或拆解某个玩家、逼问矛盾、解释票型和复盘任务压力。组队阶段会要求队伍能被公开记录解释，避免直接把私有身份视角翻译成突兀的最优车；特别是梅林不能连续按隐藏真相精准排除坏人，而要在任务成功、公开理由可信和刺杀风险之间取平衡。梅林在首轮和第二轮公开信息不足时，不应把“避开全部已知坏人”作为默认组队原则；当公开强共识正在保一个梅林私下不放心的人时，不应每次亲手拆掉，非决胜轮必须优先考虑至少一种隐藏方案：把他作为压力位/试车位暂时保留、让别人带这条线自己观察票型、自己不上车改用投票施压，或等他露出公开矛盾后再拆；在非决胜轮、公开证据不足或已经连续正确排人时，可以保留公开记录较强的争议位、扶持别人带正确方向，或把判断包装成试车/压票，而不是每次提交私下最优车；组队的 `private_reason_summary` 也应评估是否过于精准、是否会让刺客锁定自己。发言阶段会显式要求在梅林候选/派西维尔叙事、争车位、保护强势好人、压制可疑领队或拆身份叙事时，优先评估是否借派西维尔姿态；如果活动日志已经出现派西维尔、候选、保护、挡刀、假身份或装派西维尔等身份叙事，`public_message` 必须至少有一句主动处理这条叙事，可以半跳、假装保护、反跳、拆穿、把自己放到保护/挡刀位，或撤回普通好人位但同时解释自己在保护哪条线。`prompt.v10` 要求派西维尔在真梅林候选被全桌追打时至少做一层保护性混淆，例如同时评价两名候选、提醒坏人诱导刺杀、替候选争取可解释上车，或把自己放进疑似有视角的位置吸刀。`prompt.v11` 进一步要求发言中引用历史票型和言行矛盾前必须核对活动日志。身份姿态不能只出现在 `private_reason_summary`；公开发言要直接让其他玩家听出你是在保护、拆解、反跳、挡刀或借派西维尔姿态争解释权，但不要自称“保护位/挡刀位”。佯装视角可以半真半假地露出方向感，但必须可否认，不能硬报未公开候选名单、验人结果、真实阵营或任务牌提交内容。任务失败后的公开发言不要说自己提交了成功或没有出失败票；改用“从我的立场我不认这张锅”“同车其他人需要解释”“这辆车的组队逻辑需要复盘”。公开话术少用身份标签，多用动作和限定词；不要把任务说成验人，也不要空口保证自己是好人。投票阶段要求票型和最近公开发言保持可解释一致，避免“刚说反对却投赞成”或“刚说支持却投反对”的断裂。任务行动阶段要求坏人在好人已有两次成功、当前任务失败即可阻止刺杀阶段、且坏人数量足以达到失败票要求时，默认优先提交失败；只有能说明刺杀胜率明显更高时才继续隐藏。刺杀阶段要求候选排序能排除至少两个其他目标，提高刺杀理由可审计性。身份扮演是条件性策略，不是每轮机械跳身份；如果暂时不公开扮演身份，也应是有意隐藏，而不是忘记争夺身份话语权。行动提示只影响模型表达与策略倾向，不改变后端规则判定。

发言阶段的 `stance` 不是必需字段；解析层会在缺省时按 `uncertain` 处理。

## 角色与身份提示

角色基础文案分为三层：

- `role_descriptions`：本局配置中的身份机制和基本可见事实。
- `role_gameplay`：玩家视角中的默认角色玩法，包含身份目标、局势判断、身份姿态选择、话语权动作和条件性身份扮演建议。
- `role_strategy_tips`：玩家视角中的角色进阶玩法，只在进阶模式开启时展示，用于补充更细的节奏控制、隐藏/误导/保护和刺杀判断。

这些文案会按当前玩家身份展示，不会把其他玩家的隐藏身份真相暴露给当前玩家。

当前默认策略会强化不同身份的桌面打法差异：

- 好人会主动争夺可信话语权，围绕上车/下车、票型、任务结果和身份叙事逼出更多公开信息，并选择普通好人、可信上车位、强势推理位、保护位、派西维尔姿态或挡刀位等身份姿态。
- 梅林会用公开逻辑引导正确车队，通常扮演普通忠臣、谨慎推理位或愿意上车的好人，必要时短暂借用派西维尔姿态制造候选迷雾；组队前会检查队伍是否能被公开记录解释，避免连续按隐藏真相精准排除坏人，或让组队、投票和发言长期呈现同一条精准排雷线。非决胜轮可以保留可解释的不完美，例如跟随部分公开共识、放进公开记录较强的争议位，或扶持其他好人领队来降低梅林感。
- 派西维尔会在辨别梅林/莫甘娜时制造保护性模糊，必要时公开或半公开扮演派西维尔、反跳假派西维尔、扮演保护位或挡刀位，但避免过早卖出候选关系；当某个候选因持续纠偏被集火时，不应简单跟压，而应通过候选双评、挡刀、吸收视角嫌疑或拆刺客诱导来保护候选空间。
- 忠臣会更主动地要位置、逼解释、建立信任链；在争上车、保护强势好人、压制可疑领队、拆身份叙事或给疑似梅林挡刀时，可短暂假装派西维尔、反跳假派西维尔或挡刀，但不能把猜测说成验人。
- 坏人会主动选择假身份姿态，尤其可扮演假派西维尔来误导候选关系、保护错误对象、逼真视角露头或质疑真视角，同时避免固定每次强冲或每次出失败票。
- 关键任务中的坏人会优先考虑任务胜利路径：当好人已有两次成功且当前失败能阻止第三次成功时，如果车上坏人数量足以满足失败票需求，默认应出失败并准备推锅，而不是无条件隐藏到刺杀。
- 奥伯伦这类无互认坏人在候选叙事已触发时，默认要参与身份争夺，优先用保护位或假派西维尔姿态搅混候选关系，而不是只用“信息少、先观察”退出讨论。
- 刺客会结合跳身份、挡刀、被保护关系和任务纠偏记录判断谁最像梅林。

当前覆盖身份包括：

- 亚瑟的忠臣 / 忠臣。
- 梅林。
- 派西维尔。
- 刺客。
- 莫甘娜。
- 莫德雷德。
- 奥伯伦。
- 爪牙。
- 崔斯坦。
- 伊索尔德。

## 进阶模式开关

配置项：

```json
"role_tip_detail": {
  "enabled": false,
  "label": "进阶模式",
  "role_tips": {}
}
```

默认关闭。关闭时，模型仍会收到增强后的角色基础玩法，包括身份目标、局势推进、身份姿态选择、话语权动作和条件性身份扮演。

打开后，会在当前玩家自己的角色基础玩法后追加角色进阶玩法，例如更细的发言节奏、隐藏方式、误导方式、保护方式、刺杀判断方式等。模型不会看到 `role_tip_detail`、`enabled` 等配置键名。

进阶模式适合用于：

- 进一步细化角色扮演节奏和风险控制。
- 增强不同身份在压力局、关键票型和终局刺杀前的发言差异。
- 让模型更接近玩家攻略中的常见打法，而不是承担默认角色扮演的全部责任。

进阶玩法不适合写入：

- 配置说明。
- “默认开启/关闭”之类元信息。
- 当前玩家不应知道的隐藏身份真相。
- 与当前身份无关的其它身份私密策略。

## 可选机制

配置项 `optional_mechanics` 用于描述可开关机制的文案。机制是否进入模型输入由每局 `enabled_options` 决定。

当前包含：

- 湖中仙女：仅 8-10 人局可开启；第 2、3、4 次任务结算后，持有者查看一名从未持有过湖女的玩家阵营，并转交湖女。
- 崔斯坦：和伊索尔德互相确认对方是好人。
- 伊索尔德：和崔斯坦互相确认对方是好人。

只有启用后的机制才进入 `【本局配置】`。未启用机制不会显示给模型，避免模型把未生效规则当成当前对局事实。

湖女查验结果属于执行查验玩家的合法私有信息，只会出现在该玩家后续 prompt 的 `【你的视角】` 或 `【活动日志】` 中，不进入其他玩家视角。活动日志对其他玩家只展示“谁使用湖女查看了谁”，不展示阵营。

## 推荐身份组合

`recommended_role_setups` 保留为 prompt 配置中的参考信息，但当前建局规则使用后端规则层固化的 5-10 人推荐身份组合。该字段不作为运行时规则裁判来源。

该字段不直接发送给模型。模型只需要知道“本局实际身份”，不需要知道推荐表、默认表或配置来源。

当前规则层只允许 9-10 人局开启崔斯坦/伊索尔德，开启后由后端把两个忠臣替换为这对身份。

## 元信息禁止进入模型输入

以下内容不应出现在最终发给模型的 prompt 中：

- 提示词版本号。
- 配置文件路径。
- 配置键名。
- `enabled`、`default_enabled_for_player_counts` 等开关字段。
- `recommended_role_setups` 或“推荐身份组合”。
- “默认不加入推荐身份组合”。
- “可选扩展身份”等配置性质描述。
- 原始 JSON 上下文字段名。

如果需要记录这些信息，应保存在 AI 决策日志或配置文件中，而不是发送给模型。

## 相关代码

- `backend/app/services/game_service.py`：在对局推进中触发 AI 行动，保存 AI 决策日志和 `prompt_messages`。
- `backend/app/ai/player.py`：AI 决策调用链；`AiPlayer._decide()` 负责构造上下文、拼接 prompt、调用模型、解析输出并记录 token/cache usage。
- `backend/app/ai/context.py`：构造 `AiContext`、`stable_prefix`、`stable_prefix_hash`、动态上下文和当前阶段合法动作。
- `backend/app/prompting/templates.py`：最终 prompt 拼接入口；`PromptBuilder.build_messages()` 生成模型 `messages`，同文件负责玩家视角、固定动作格式声明、活动日志、本次行动和事件文本渲染。
- `backend/app/prompting/config.py`：加载和校验 `prompt_templates.json`。
- `backend/app/prompting/schemas.py`：解析和校验模型 JSON 输出，非法输出会交由后端规则校验或触发 AI 决策错误。
- `backend/app/llm/provider.py`：把 `messages` 放入 OpenAI-compatible Chat Completions 请求体，并读取 token 与缓存命中用量。
- `config.example/prompt_templates.json`：可提交的默认提示词文案、角色标签、事件模板和动作输出契约。

## 维护建议

- 修改提示词展示结构时，优先检查最终生成的 `prompt_messages`，不要只看配置文件。
- 修改文案、角色标签、事件模板或动作输出契约时，优先看 `config.example/prompt_templates.json`。
- 修改拼接顺序、消息 role、玩家视角、活动日志或本次行动格式时，优先看 `backend/app/prompting/templates.py` 和 `backend/app/ai/context.py`。
- 稳定前缀只放固定系统规则和本局固定配置；玩家身份视角、公开事件历史、当前阶段、合法动作等动态内容必须放在 system message 之后。
- 当前“增量”优化指让每次请求的前文保持一致，并让活动日志按事件时间顺序追加，避免重排、合并改写旧记录或重复声明常用动作 JSON 格式；OpenAI-compatible Chat Completions 仍然是无状态请求，不应假设 API 只接收 delta 或自动记住上一轮上下文。
- `assassinate` 和 `use_lady_of_lake` 不应进入固定动作 JSON 声明，只在实际请求对应行动时临时声明。
- 需要排查缓存效果时，看 AI 决策日志中的 `stable_prefix_hash`、`prompt_tokens`、`cached_tokens` 和 `cache_hit_rate`。
- 增加角色时，至少补齐身份标签、机制说明、玩法、策略、合法视角规则。
- 增加开关时，区分“配置给系统看的内容”和“模型需要知道的游戏事实”。
- 测试应优先覆盖长期行为，例如合法视角、不泄露原始 JSON、投票和任务结果可读，以及目标、上车/下车、质疑/反跳、合法信息边界等行为关键词簇，而不是绑定某一句攻略文案。
